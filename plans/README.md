## Follow-ups noted in review

- From plan 001: `docs/language-spec.md` §6 says array initialiser lists and array parameters give "SYN-UNSUPPORTED-FEATURE or SYN-EXPECTED-TOKEN". Under the catalog's code-selection rules they actually produce SYN-EXPECTED-EXPRESSION (`= {`) and SYN-EXPECTED-TOKEN (`int a[]` parameter). The milestone-1 parser plan should detect both explicitly and emit SYN-UNSUPPORTED-FEATURE, then tighten §6.

- From plan 003's re-trace against plan 002 (the corpus found these design gaps; fix them in the milestone-1 plan by amending `docs/error-recovery.md`, then re-trace the affected sidecars):
  1. **Unsupported pointer declarations lose the name.** In `int *values;`, the IDENT is never consumed, so `declared_names = []` and the 5 later uses of `values` become unlinked SEM-UNDECLARED-VAR (`dev/049`). The fix is for panic over `type_spec "*" IDENT` to add IDENT to `declared_names`, so R5 links the uses.
  2. **`switch` bodies produce unlinked `break` errors.** `heldout/020` gives 3 SEM-BREAK-OUTSIDE-LOOP with no `caused_by`, because R7 covers only while/for orphans. The fix is to extend R7 to orphan blocks of a SYN-UNSUPPORTED-FEATURE statement.
  3. **Compound assignment counts as a read.** `+=`, `-=`, `++` and `--` read their target (the corpus assumed this). Write it into `docs/error-recovery.md` §6 and the `sem.unused_declaration` wording.
  4. **Code selection when the expected set is {expression, `)`}** (e.g. `printf(` followed by a keyword). The corpus assumed SYN-EXPECTED-EXPRESSION (`dev/002`, `dev/046`, `heldout/010`). The parser plan must state this explicitly.
  5. **Trivial note error:** the `dev/051` sidecar note says `n` is "read again on line 11"; it is line 10. Fix it in passing.
- **F2 metric definition (advisor decision).** The cascade set is the programs with `cascading: true` (traced raw ≥ 2): 15 dev and 8 heldout. For part (b) of plan 002 §10 (displayed = 1), only single-fault files count. Multi-fault files (`dev/060`–`063`, `heldout/019`) count in the part (c) raw-vs-displayed sum, with expected displayed = their number of roots.

## Cross-plan decisions (advisor, 2026-10-10, during review of 002/003)

- **Missing `}`**: a phrase-level repair (plan 002 decision 9 / §4.7). `type IDENT (` inside a block gives one SYN-UNBALANCED-BRACKET at the type keyword, closes the open blocks, and the next function parses normally. Plan 003's location convention assumes this.
- **EOF location**: immediately after the last token (plan 002 §8). Plan 003 requires every corpus file's last line to contain code, so this equals the file's last line. SEM-MISSING-MAIN is reported at EOF.
- **First bad character**: the first character of the rejected lexeme (`12abc` → the `1`).
- **Missing `;` code selection**: `expected` is what the failing `expect()` required (plan 002 §4.1), so catalog rule 2 selects SYN-MISSING-SEMICOLON after a declarator. No catalog change is needed.
- **Record fields**: plan 002 adds `language`, `caused_by`, `span_end` and `message` (PRD F1 lists `message`, but the PRD schema table omits it). `root_id` = own id for roots; `caused_by` = None when no cause is known.
- **`<error>` type**: it passes type checks silently (no record); shape checks still fire and are linked (R3).
- Plan 003's extras are accepted: `tests/corpus_lib.py`, the trailing-newline and valid-program schema rules, and `pythonpath = ["src"]`.
